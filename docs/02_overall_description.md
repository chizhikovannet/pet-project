Общее описание

2.1 Общий взгляд на продукт

Веб-сервис «RoomMate Finder» представляет собой специализированную платформу для студентов, ищущих сожителей для совместного найма жилья. Сервис функционирует по клиент-серверной архитектуре, где серверная часть предоставляет RESTful API для обработки бизнес-логики, а клиентами могут выступать веб-приложения или мобильные клиенты.

Центральной особенностью системы является сочетание анкетного подбора по бытовым критериям (бюджет, ВУЗ, привычки, район) и системы рейтинга и отзывов. Рейтинг формируется на основе оценок от других пользователей (например, бывших сожителей или участников прошлых диалогов) по критериям надежности, соблюдения чистоты, платежеспособности и коммуникабельности.

2.2 Классы и характеристики пользователей

В системе выделяются следующие роли пользователей:

Гость (Неавторизованный пользователь):

Имеет доступ только к страницам регистрации и авторизации.

Не имеет доступа к поиску анкет, просмотру контактных данных и отправке сообщений.

Студент (Авторизованный пользователь):

Проходит регистрацию и заполняет собственную анкету.

Имеет доступ к поиску и фильтрации анкет других студентов.

Может добавлять понравившиеся анкеты в «Избранное».

Может создавать личные чаты и переписываться с другими пользователями.

Имеет право выставлять оценки и оставлять отзывы другим пользователям, формируя их рейтинг.

Администратор (Модератор):

Обладает расширенными правами по управлению контентом.

Осуществляет модерацию анкет и отзывов на предмет нарушений (спам, ненормативная лексика, фейковые аккаунты).

Может блокировать или архивировать нарушающие правила аккаунты.

2.3 Операционная среда

Серверная часть (Backend):

Среда выполнения: Python 3.11+

Веб-фреймворк: FastAPI

СУБД: SQLite (для разработки и локального тестирования) / PostgreSQL (для продакшн-среды)

Веб-сервер: ASGI (Uvicorn / Gunicorn)

Клиентская часть (Frontend / API-клиент):

Любой современный веб-браузер (Chrome, Firefox, Safari, Edge) с поддержкой JavaScript.

Интерактивная документация Swagger UI для проверки и отладки API.

2.4 Ограничения дизайна и реализации

Технические ограничения:

Аутентификация должна осуществляться через передачу JWT-токенов в заголовках запросов (Authorization: Bearer ).

Пароли пользователей должны храниться в базе данных исключительно в зашифрованном виде (с использованием хэширования bcrypt).

Бизнес-ограничения:

Один пользователь может владеть только одной активной анкетой.

Повторная оценка одного и того же пользователя разрешена только при условии завершения совместного периода проживания или подтвержденного взаимодействия, чтобы исключить накрутку рейтинга.

Ограничения по времени и ресурсам:

Проект разрабатывается в рамках диплома, поэтому первичный запуск фокусируется на работе с REST API и серверной логикой без сложной внешней инфраструктуры microservices.

2.5 Предположения и зависимости

Предположение 1: Пользователи предоставляют достоверную информацию о себе, своем ВУЗе и бюджете.

Предположение 2: Пользователи имеют доступ к сети Интернет для взаимодействия с API.

Зависимости: Стабильная работа сторонних библиотек Python (Pydantic, SQLAlchemy, PyJWT, Passlib).
